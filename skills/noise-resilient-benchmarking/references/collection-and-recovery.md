# 补缺、记录、诊断与恢复

用于记录档位选择、低接收率/拒绝诊断、预算检查、暂停恢复或进程续接。按主流程执行完整组，不为了补缺重建整个框架。

新增分档记录/审计或更细的拒绝分布诊断等增强时，须先在本项目验证相应能力，再纳入正式合同；只验证拟采用的增强，不要求先实现全部可选增强。既有已验证且仍有效的冻结规则继续沿用，不因此无故重验或改动协议。

## 队列与真实进程身份

完整配对组是接收、保存、重试的最小单位。尝试绑定场景、冻结配置、原顺序槽、真实周期。失败整组回原槽；可以先补其他预定缺口。新尝试从头测全部对照，不能拼成员成绩。最终合格组满足顺序配额和组跨度。

记录周期 ID、真实 PID 集合和必要启动身份；新进程不能冒充旧进程。已有完整组保留真实周期。若合同要求完整进程周期，残片不能拼成一个完整周期，须按合同补齐重复。大量同进程调用/组不自动成为独立实验。

无独立次数上限时用原 `D` 约束持续尝试；有上限则累计继承。不额外加任意小额重试限制。接收率低但仍能接收完整组，预算内继续补缺。全部尝试长期不可测、计数恒定异常或边界始终超限时停止无效循环，检查接口、粒度、批长；诊断不降门槛，参数变化须重新校准并建立新配置。

入口无法执行时用冻结短等待/有上限退避。新协议可从 1 秒等待开始评估，但须确认并冻结，不作为现有协议的替代默认；不新增连续几十秒低负载等待，不忙等，等待计入适用预算。

## 拒绝不对称与提前终止

按冻结间隔，对每个实现、执行位置、顺序汇总：实际执行数、合格数、无效数、证据不足数、原因码数量。数量和分母同时报告。角色拒绝率分母为该角色**实际执行次数**，不是组尝试数，也不是计划执行数。

冻结策略允许提前结束明确无效的组；未执行成员记 `NOT_EXECUTED`，不计拒绝、不伪记合格。仅首个失败成员可见时说明诊断覆盖有限，不能把后续未执行者当没有问题。

发现一方/位置更易被排除，检查批长、观察误差、启动状态、调度条件，也检查实现本身的等待、分配或资源行为。不能统一归因外部 CPU，不能删正常工作、放宽门槛、删合格慢值或选有利顺序。若选择机制使证据不能支持合同结论，报告不明确，按批准流程修正协议。

## 两种记录档位

正式采集前冻结模式、提交间隔、诊断样本配额/选择方式；现有逐次证据要求继续用审计模式。

| 内容 | 轻量 | 审计 |
| --- | --- | --- |
| 必需指标及全部质量判断 | 全部执行 | 同样全部执行 |
| 合格完整组 | 完整保存 | 完整保存 |
| 无效/证据不足 | 累计角色、顺序、原因码计数 | 每次最小记录并保留累计计数 |
| 拒绝详情 | 冻结策略下有限诊断样本 | ID、成员状态、原因码、最少触发原始值 |
| 程序错误 | 足以定位的上下文 | 相同要求 |
| 统计/完成判定 | 冻结规则 | 相同规则 |

新项目无逐次审计要求可优先评估轻量模式。轻量减少分配、序列化和 I/O，不减少检查/有效性规则或取消预算/次数。诊断样本按事先规定的先后、间隔或触发保留，不按耗时或胜负选。轻量报告不能声称保留全部尝试原始记录；负面证据和错误不因最终通过而删除。

## 合格组、提交与计数的最小证据

每个合格组完整保存：

- 协议/配置身份、场景/输入指纹、组 ID/顺序槽；
- 周期/PID 集合、各方实际加载身份；
- `n`、`T`、`T/n`、必需快照/读取边界、质量派生值/判断；
- 组跨度、真实时间、提交状态。

大输入用可核验引用。统计、报告、落盘在目标计时外；按冻结间隔追加提交，完整组为原子证据单位。只有已提交且能核验的完整组进入恢复进度和统计；临时组、未提交尾部、半组不计完成。

轻量计数按冻结策略持久化；崩溃后无法精确恢复的部分标未知或下界，不报精确零。严格限额须保守恢复，不能凭日志缺失多拿次数。唯一尝试 ID 分段预留/保守占额仅在严格限额或崩溃审计需要时采用，不要求所有微基准增加框架；采用时冻结段长，不能证明执行的预留部分记 `INCOMPLETE` 并按合同保守占额。其他实现也必须防止恢复清零。

## 预算、退出、恢复

开始前持久化预算口径、起点、原截止、已有占用、保存清理预留，以及已批准的另列预算或排除区间及其依据。校准、预试与正式采集统一遵循 [准备路径与预算口径](calibration-and-quality.md)；既有口径与新要求冲突先按原批准流程处理，不擅自扩大预算、新增排除项或延期。

总预算、阶段预算和单进程限制分别管理。进程到自身限制后，环境支持且总预算允许，可续接合法缺口；不获得新总预算。每组前检查剩余预算能容纳下一组与保存清理。

暂停/取消/到原截止/原次数耗尽后停止新增测量，保存已提交完整组、缺口、准确恢复点，丢弃未完成临时组。系统阻塞导致实际退出晚于截止须单列，不倒改时间或数据。

恢复继承原截止、已用次数、冻结配置、进程身份、提交记录；核对源码、产物、环境、输入后只补合法缺口。不可核验记录不计合格覆盖。新建配置也不刷新预算。
