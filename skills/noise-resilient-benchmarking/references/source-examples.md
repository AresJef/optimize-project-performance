# 来源示例与使用边界

仅在需要查对历史项目参数或解释为何不能通用化时读取。以下参数来自项目历史测量规范，不是当前项目的默认值或授权。

本 Skill 整理时只做结构与文本情景验证，未核查历史项目的当前工具实现，也未执行真实平台性能测试。历史规范称第一个示例来自已验收协议；这是历史记录，不是本 Skill 对现有实现的验收。可选增强须在采用项目中验证后再写入正式合同。

## 项目一：来源中的同步单线程 CPU 密集型热调用示例

| 项目 | 来源参数 |
| --- | --- |
| 批次目标 | 约 1 ms；校准验证为最快实现留约 0.5 ms 时长余量 |
| 正式最低批次时长 | 0.2 ms |
| off-CPU 代理上限 | 10%，同时检查既定边界/计数条件 |
| 快照边界额外时间/批次耗时 | 不超过 50%；不是 off-CPU 误差界 |
| 系统 CPU 忙碌 | 有效累计 tick 增量至少 10 时，不超过 75% |
| 负载/内存 | load/逻辑 CPU 数不超过 0.8；可用内存至少 3% |
| 三方组跨度 | 不超过 250 ms |
| 初始/追加 | 六种顺序各一组；进一步判定的不明确场景按预定规则补至十二组 |
| 进程/等待 | 每三组一个新 worker 周期；环境忙默认等待 1 秒 |
| 诊断指标 | 非自愿切换、核心占比、频率不作默认硬门槛 |

这些规则不等于 `q±e` 增强，也不证明约 1 ms 对所有平台、调用或目标可靠。来源明确不表示 `q±e`、分档审计、更细拒绝分布诊断等可选增强都已在该项目实现。
