# 合同、校准与质量证据

用于性能优化计划中的测量与例外证据准备、新建/补齐合同、准备度核查、选择批长、稳定性/预算预试、重验依赖或处理分辨率/误差问题。仅规划时明确要求与待验证项，不执行测量。正式采集已有有效冻结配置时，无须为了执行普通补缺重建这些设计。

## 冻结配置应能恢复的字段

已有项目先保存当前批准协议与配置摘要。新建或补齐测量设计时，先明确目标、质量标准、统计口径、可试窗口、允许的时间与停止条件。选定并校准起步窗口后，在正式采集前保存下表各项。

| 配置项 | 必须明确 |
| --- | --- |
| 协议身份 | 协议版本、测量程序版本、配置哈希、适用范围 |
| 比较对象 | 源码、构建方式、产物、实际加载路径、运行环境 |
| 场景与输入 | 唯一场景 ID、输入描述/引用、内容指纹、调用方式 |
| 计时边界 | 初始化、分配、释放、输出消费、等待是否属于被测工作 |
| 状态策略 | 预热、缓存、GC、输入复用/重置、结果处理 |
| 批量次数 | 每场景共同 `n`、最低可测长度、校准身份 |
| 统计分组 | 是否分组；每统计批次完整组数 `k`、批次数 `b`、入组边界、汇总公式 |
| 对照覆盖 | 合格组数、各顺序配额、最大组跨度、追加上限 |
| 进程重复 | 周期定义、周期内组数、要求的真实重复数 |
| 质量规则 | 必需/诊断指标、门槛、分辨率要求、边界误差条件 |
| 统计与判定 | 配对倍率方向、主要统计量、稳定性指标/门槛、充分性要求、性能目标、单项退步上限 |
| 稳定性采用例外（拟使用时） | 该项最低有意义收益、保守收益估计方法、需核对的分组与顺序、独立复测要求及批准权限；已有明确目标符合这些用途时直接引用。 |
| 等待与诊断 | 短等待、有上限退避、诊断间隔、持续不可测处理 |
| 预算 | 总预算 `D`、起点、原截止、清理预留、既有尝试上限 |
| 记录策略 | 轻量/审计、诊断样本配额及选择方式、提交间隔、恢复规则 |
| 测量与补测 | 一套正式比较的轮次和独立进程、额外补测的触发条件与用户确认的剩余额度、套内恢复与追加条件。列明允许调整的参数、容差和调整次数。 |
| 准备证据 | 场景与代表性、历史窗口及依据、各档探测与校准的配置和依赖指纹、原始读数位置、有效组数与尝试总数、实际成本及预算可行性 |

没有可靠业务频率不编造权重。需要总体成绩时，事先说明权重来源、汇总方法与含义；总体提升不能抵消必须达标场景的退步。统计设计细节仅在确定/改变统计或判定时读取 [statistics-and-remeasurement.md](statistics-and-remeasurement.md)。

## 可测长度与依赖校准

1. 验证时钟单调性、实际分辨率和读取成本，验证质量接口单位、计数粒度、观察覆盖区间及开销。计时单位的细度不等于真实精度。
2. 按最快实现选择共同 `n`，同时验证最慢实现和完整组跨度；单次足够长可取 `n=1`。完整工作量和计时语义保持不变。
3. 用紧邻、顺序平衡的短批和较长控制批，按事先确定容差检查归一倍率及边界误差。超限先查时钟、状态、预热、缓存等原因，不选成绩较好的一组，不把所有差异归因于计时器。
4. 批次过短、计数粒度不足或边界误差过大时适当延长并重验。加组数不能修复单批证据不足；延长批长不自动减少冻结的覆盖/进程重复。批长和组数共同控制成本，不能无依据同时放大。
5. 保存校准身份和依赖指纹。时钟、运行时、接口变化重验对应能力；硬件、配置、构建、场景变化重验受影响项。仍有效的校准可复用，旧 `n` 仅作候选，必要验证仍执行；校准数据不计正式结果。

改变正式配置时须有独立配置身份，具体重测/复用规则见 [statistics-and-remeasurement.md](statistics-and-remeasurement.md)；新建配置不延长原预算。

## 准备路径、有界预试与最终冻结

### 协议、准备证据与预算口径

先读项目批准的范围、参数调整权限和质量判据，确认探测时限、正式轮次和补测额度。本轮已有适用的冻结配置与准备证据时，沿用该配置。需要重新定窗口时执行[起步窗口与快速选窗](../SKILL.md#起步窗口与快速选窗)。

按项目批准的口径记录探测与校准、启动与预热、等待与重试、正式采集、诊断验证和收尾的实际时间。续接时读回原起点、截止、累计用量及另列预算或排除区间，并保留其批准依据。准备阶段的耗时也要入账。变更计时口径或扩大额度，依原授权办理。

### 从探测起点到逐项开测

1. **核实是否有可比历史。** 对齐入口、输入规模与分布、执行方式、依赖环境及计时边界。记录建议起点和来源。输入结果或工件身份异常时先处理相应错误。
2. **用正式口径做小范围预试。** 从不同规模、最快、最慢及噪声敏感的场景中选代表。沿用正式调用的输入、工作量、结果消费、冷热状态、计时边界、统计单位、估计方法、平衡顺序和每组质量检查。探测可以少取样本。按每档的配置与原始读数给出建议，推荐值只用于决定接下来校准哪一档。
3. **按失败原因有限调参。** 短长批差异大时按入口规则选下一档。有效组太少时，先查组跨度、调度或等待，再判断调窗口是否有用。在项目预先授权的范围内，可以调整批长、共同调用次数、采样量或等待节奏。每次记清改什么、要验证什么和何时停止。按测量可靠性与成本选参数，禁止按候选的加速比分档。变更估计方法、统计单位、顺序平衡、正式覆盖或质量门槛，须按项目权限另定协议。
4. **用实际样本核算完成成本。** 记录各档探测用时、有效组数、尝试总数和拒收原因。以从选窗到校准通过的总耗时、失败校准次数评估工具是否省时。测量耗时会影响排期时，先查可比记录，分别取得被测操作本身的耗时，以及一次代表性完整对照从准备到得到有效结果的实际总耗时。缺少实测依据时，在已授权的代表性试跑中补记缺项。用完整对照的实耗和有效样本接收率估算正式配额、各进程及验收收尾所需的时间，注明估算的不确定性。若准备或等待占了大头，优先查对应步骤，保留每方所需的独立起始状态。
5. **按原清单逐项核准。** 同类场景可共用建议窗口，各项用自己的实际输入和当前工件完成校准。将正式配置绑定到本项校准回执，按主流程的预算与准入条件冻结开测，逐行回填结果和缺口。预试、校准各自留存配置及原始证据，使推荐依据和准入读数可复算。正式配对、统计批次及独立进程数只从正式记录计算。

## 稳定性采用例外的证据准备

仅在项目拟使用稳定性采用例外时准备，不要求所有测量任务预先设计例外。正式测量前明确该项最低有意义收益、保守收益估计、需要核对的分组与顺序、独立复测要求及批准权限；已有性能目标和协议能够提供这些依据时直接引用，不另设重复门槛。采用条件见 [单项稳定性采用例外](statistics-and-remeasurement.md#单项稳定性采用例外)。

旧项目缺少这些条件时，先核对原目标和现有证据能否满足要求，不能根据已见收益倒定门槛或事后挑分组。仍有缺项时，提出有界补充验证方案，按授权明确新增条件，并用之后独立取得的数据核验；旧数据保留原身份与严格结论，不冒称按新条件预先设计。不能完成必要补证时，不自行批准例外，也不让该项缺口阻塞无关场景。

## 组内质量判定

每短批按主流程保存 `T`、`n`、`T/n`、必需快照及其读取边界，单位一致。检查批长、覆盖边界、计数合法性、必需资源条件、适用调度代理；判断不得修正或拟合目标耗时。

| 情形 | 处理 |
| --- | --- |
| 正确性不符；必需指标不支持/单位错/计数异常；身份或配置错误 | `ERROR`，停止无效循环并诊断修复 |
| 暂时分辨率不足或必需证据不足 | `INSUFFICIENT`，整组不接收 |
| 诊断指标不可解析 | `UNRESOLVED`，保留状态，不伪造数值、不单独否决其他必需证据充分的组 |
| 必需质量规则全通过且完整组/跨度符合 | `VALID`，仅可参与比较，仍需整体稳定性及性能判断 |

系统累计计数增量不足不能解释成零负载。必需指标按冻结充分性要求处理；诊断指标不临时升级硬门槛。属于实现的正常等待、分配或资源行为不能统一当外部干扰删掉。

## 同步单线程 CPU 密集型场景的 off-CPU 代理

适用时可用 `q = (T − ΔCPU_thread) / T`。`ΔCPU_thread` 是**测试线程**累计 CPU 时间增量，与墙钟 `T` 的覆盖区间、单位和读取误差须经过验证。多线程进程 CPU 时间不能代入此单线程公式。

保留原始有符号差值，不把负值截为零。负差超过已验证误差范围时停止并诊断时钟、单位、边界或批长。既有项目沿用批准的代理门槛与边界条件。`q` 是操作性干扰代理，不是无误差的真实 off-CPU 比例；线程 CPU 时间接近墙钟不能排除频率、缓存、温度或争用影响。

I/O、异步、多线程、GPU 另定适用规则，不能套此公式删掉自身必要等待。热调用、冷启动、内部核心各自冻结边界和质量规则，不能相互替代。

## 可选 `q±e` 增强

仅在项目决定采用并完成校准、纳入新协议后执行；已经采用的增强正式采集中不能停用。

`e` 是对应本批次的无量纲比例误差界。保存计算方法、校准证据、适用批长、时钟/接口依赖、有效期、重验条件。来源覆盖墙钟与线程 CPU 时间的分辨率、读取区间不匹配及相关边界误差。时间误差转为比例须说明分母。

不能把快照总开销占比直接当 `e`，不能凭计时单位推断精度或任定一个看似合适的值。经验校准界须说明证据性质，不冒充数学保证或置信区间。

冻结上限为 `h` 时：

| 条件 | 该项判断 |
| --- | --- |
| `q + e ≤ h` 且其他必需条件全通过 | 通过 |
| `q − e > h` | 不合格 |
| 其余情况 | 证据不足，整组不接收 |

没有有效 `e` 不能退回直接比 `q` 宣布通过。先诊断或延长批次；要改协议，按独立配置和重测规则处理。未采用增强的旧数据不能宣称通过增强标准。
