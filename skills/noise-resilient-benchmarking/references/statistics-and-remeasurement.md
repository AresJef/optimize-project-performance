# 统计、有限复测与报告

用于汇总/判定、统计分组、逐项补证、收齐后不稳定、有限复测、场景级复用或单项稳定性采用例外。采集前准备与逐项冻结见 [calibration-and-quality.md](calibration-and-quality.md)。已有冻结规则继续用，不因看到成绩重选估计量、显著性体系或停止规则；获批新协议保留独立身份和旧证据，不追溯改判。

## 统计分组不默认增加采样

逐场景汇总各方**全部**合格值的中位数、平均值、波动、范围。配对估计量按合同：逐完整组计算倍率后汇总，或在统计批次内先汇总各方耗时/调用次数再比；二者不混称、不事后互换/择优。汇总耗时方法的每调用平均为 `ΣT / Σn`，再按冻结方向算倍率。

若采用统计分组，分别记录短批调用次数 `n`、每统计批次完整有效组数 `k`、场景批次数 `b`，以及真实进程周期对应关系。按准备流程最终冻结批次边界、入组顺序、必要时间跨度、顺序平衡、跨批波动规则，再开始正式采集；不能事后按快慢拼批，校准/预试数据不计正式组、批次或进程重复。

优先用已采集完整组或既有进程周期，只增加计时外汇总。统计批次是逻辑分组，不是连续计时，也不自动成为独立实验；内部调用、完整组、统计批次、进程重复分别计数。已有跨进程方向/噪声筛查不要求重建采样层。延长批长不能替代必要重复。

预试前明确稳定性指标、判断层级、门槛、充分性及证据不足条件。`k`、`b` 与批长在预授权范围内按可靠性及完成成本校准、预试并最终冻结；波动界不因预试或正式成绩放宽，不从来源项目复制规模。短组质量合格不等于样本充分；小样本操作性噪声筛查不冒充置信区间。所有合格快慢组均参与，不选最快、不拟合时间、不用分组隐藏不利值。无可靠业务频率不造权重，总体提升不抵消约定单项退步。

## 收齐后仍不稳定：有限路径

先确认数量、顺序、真实进程重复和必需证据收齐，再按合同检查稳定性/充分性。单组质量好、覆盖完整均不保证统计可靠。

1. 保存本轮全部合格数据、统计结果和未决原因，固定问题项清单及其确定依据；不删慢组、不追溯改判。
2. 逐项诊断批长、时钟/读取边界、组跨度、进程状态和工具开销，确定下一可行办法、预期证据、预计用时和检查点；不直接重跑完整矩阵，也不只登记问题后搁置。
3. 在既有授权范围内做有界验证。需要短/长控制时，用少量问题场景紧邻、顺序平衡地比较，按冻结容差判断，校准样本不入正式成绩。一条路径无效时改用能取得新证据的办法，不无信息增益地重复。
4. 某项完成所需验证且预算允许，即冻结该项新配置并完成有限正式复测，不等整份清单同时就绪。保留所有问题项的结果与未决状态；其他项只在下述全部复用条件满足时保留。
5. 单一路径次数用尽但仍有可行新办法和预算时，提出有界下一方案。超出允许参数、次数或其他协议条件时，先取得必要决定再建立新协议，不刷新旧限额或混入旧样本。没有可执行办法或已到批准边界时，保存准确缺口和恢复条件；仍不明确报 `INCONCLUSIVE`，稳定且充分的数据证明未达性能门槛时报 `FAIL`。
6. 待确认不自动阻塞其他场景或项目。只有它是当前采用或交付的实际必需依赖，且无法通过可行办法在授权和预算内解决时，才限制受影响部分；其他独立查证继续。收益方向明确而仅稳定性超限时，可按下文审议采用例外，严格成绩不变。

触发、问题项确定方式、允许参数/范围、验证容差、调整次数和复测上限须按当前批准协议明确。协议变更保留原规则、已用次数、时间账和全部旧数据；已授权的局部调整不额外扩成全矩阵。不能为得到胜出成绩不断延长批次、重开队列、放宽质量门槛或选择性保留结果。

## 补缺、追加、协议重测的区别

| 条件 | 行动 |
| --- | --- |
| 同配置缺合格组 | 保留已合格组，只补原顺序槽 |
| 预定规则要求追加 | 保留初始组，按冻结追加顺序/上限扩展 |
| 输入、工作量、计时边界、实现身份或质量规则改变 | 独立配置身份的新采集批次，保留旧证据，不混合凑数 |
| 预定场景级采样调整经验证 | 独立场景配置，完整重测指定项；其他项仅在下面全部条件满足时复用 |
| 合同要求独立复测 | 新真实进程周期/约定独立环境完成所需覆盖，不复制主测时间 |

普通补缺不要求整项替换。决定在新配置下重测整个场景后，以新的完整结果作该批次结论，变差也采用；不同协议/身份可以分别展示，不择优替换。参数复用须依赖指纹、来源、冻结规则匹配且合同允许，参数复用不等于成绩复用；更换产物后不能把旧成绩当当前成绩。

新配置不延长任务截止。收齐后不因成绩不理想继续采样，不反复重开同协议；到追加上限仍不明确如实报告。

## 场景级局部复用：必须同时满足

仅用于事先声明的有限局部修正后的**场景级结果组合**，不能跨配置拼样本：

1. 问题项按预定稳定性/精度规则确定，修改前固定替换集合，不按胜负选择。
2. 比较对象代码、产物、runner/helper、输入、实际输出、冻结环境身份、计时语义、性能目标、权重均一致。环境一致是身份和质量条件匹配，不要求两时点瞬时 CPU 值相等。
3. 只改预先允许的场景级采样参数，逐项列变化并绑定新校准证据；质量门槛、顺序平衡、必要重复不降低。
4. 每指定场景独立重新完成全部对照、所需统计批次、顺序配额和进程重复。可以逐项完成并登记，不要求所有指定项同时就绪；完整新结果替换该项旧结果，变差也采用。其余指定项继续保留未完成或不明确状态，不撤销替换任务、不回退旧较好成绩；最终汇总包含完整指定集合及各项真实状态。
5. 保留的其他项依赖/原始证据可核验、不受调整影响，原已满足稳定性/充分性。
6. 不跨配置组成一个配对组或统计批次。总汇总用约定场景级统计量/原权重，不因批长增加而提高权重。
7. 保留原失败/复测记录，逐场景列采用原始记录、实际配置、校准证据、进程身份、替换关系、状态；组合后重做全部既定汇总/验收。

**用小范围测试解释原有退步时**，先核对同一候选、参照和输入在小范围内是否仍出现原来的变慢。能重现，就用小测试继续定位。若差距消失或快慢反转，分别保留两份结果及其适用范围，核对前面运行过哪些用例、执行顺序和进程状态。要将小范围结果计入原范围的验收，仍须满足原协议和上述复用条件。

代码、产物或公共测量逻辑变更不自动适用；不能证明未受影响项依赖和口径匹配就不复用。此例外不延预算、不允许无限复测或择优组合。

## 单项稳定性采用例外

提速方向清楚与提速幅度足够稳定是两个问题。只有该项收益方向明确、采用价值足够且唯一剩余超限为稳定性时，才审议采用例外；原门槛和严格判定不变。本节不授予批准权限，也不能用于真实速度退化。

1. **核对同一比较与必要证据。** 候选及对照产物、公开入口、输入、工作量、结果、ABI、依赖和计时边界一致可核验。正式覆盖、样本量、顺序配额、真实进程重复、机械质量、必要精度及收益判断所需证据满足要求；功能和安全保护通过。身份错误、正确性问题、缺覆盖或精度不足不得借稳定性例外采用。
2. **证明该项自身的收益。** 用完整正式数据及独立复测，核对两轮结果以及预先定义的分组和顺序均支持同向收益。按预定保守估计，收益须越过测量误差并达到最低有意义收益；报告两轮绝对时间、最差组、快慢样本范围和剩余不确定性，幅度写为实测观察。不能用其他项的收益替代本项证据，也不把来源案例的全部配对同向、样本数或百分比设为通用条件。所需条件的准备及旧项目缺项处理见 [例外证据准备](calibration-and-quality.md#稳定性采用例外的证据准备)。
3. **核对完整必要保护。** 其他必要项按原门槛通过，或有各自明确批准且仍适用的采用条件。真实速度退化交由项目的产品修正与收益代价流程处理。采用当前产物仍缺必需条件时，只限制该产物的采用，不因这项待确认停止其他独立查证或可独立验收的工作。
4. **批准绑定产物与范围。** 记录候选及对照指纹、场景、ABI、依赖和配置、原门槛及实测值、收益与代价、补证尝试、批准人及权限依据、适用范围和重核条件。项目明确委托时，执行者在授权范围内决定并记账；超出委托由项目责任人决定。可以一次批准明确列出的多项，但每项独立核对证据和条件；某一场景、ABI 或对照获批，不自动批准其他比较。
5. **并列保存严格成绩与采用状态。** 正式比较保留 `INCONCLUSIVE`（项目使用 `INC` 时沿用）、全部原始数据、旧失败和复测记录，采用状态另记“按该项稳定性例外采用”。例外只适用于绑定的产物和比较条件；后续候选按自身数据审查，不默认继承例外或旧成绩。仍可进一步查清的测量问题保留下一办法及恢复条件，在授权和预算内主动补证，不因已经采用就删除未决记录。

## 覆盖、质量、稳定性、性能分别报告

逐场景及验收范围分别给数量、适用规则、证据和判断：

- **覆盖**：场景、合格组、各顺序配额、真实进程重复、必需证据是否完整；
- **质量**：采用组是否通过全部必需检查，诊断不可解析/错误情况；
- **稳定性**：合同层级的波动与充分性是否满足，精度不足/未决原因；
- **性能**：按下表及原合同给出严格状态。收益方向的额外证据和获批采用条件另列，不以采用决定替代严格判定。

| 类别 | 状态 | 含义 |
| --- | --- | --- |
| 采集 | `COMPLETE` | 全规定场景、合格组、顺序配额、真实重复、必需证据收齐 |
| 采集 | `INCOMPLETE` | 暂停、预算或退出条件后仍有缺口 |
| 采集 | `ERROR` | 程序/正确性/身份/单位/必需接口问题必须修复 |
| 性能 | `PASS` | 合同覆盖、质量、稳定性、充分性满足且全部性能门槛通过 |
| 性能 | `FAIL` | 满足合同的有效、足够稳定且充分数据证明某门槛未通过 |
| 性能 | `INCONCLUSIVE` | 证据/精度不足或波动过大，不能可靠判定 |

`VALID` 仅组可比较；`COMPLETE` 可为 `FAIL` 或 `INCONCLUSIVE`。中位观察值达到目标而稳定性/充分性未过，性能仍 `INCONCLUSIVE`；稳定性失败不证明性能失败。修复前的 `ERROR` 不转成正常性能判断。不能仅输出中位成绩或总 `PASS`。

最终报告至少含：配置与复现命令；校准/预试准备证据及预算可行性记录；对象及加载身份；计时边界；各场景调用数/完整组数；采用时的 `k`/`b` 与公式；顺序配额/真实进程重复；全部合格数据位置；四项判断及门槛对照；拒绝/证据不足计数与实际分母；诊断覆盖；记录档位；预算使用/缺口。有限调整或局部组合另附调整记录、逐场景来源清单、旧失败证据及未完成项的下一办法和恢复条件。有采用例外时，另列收益方向证据、批准记录、适用产物及范围、重核条件，与原严格成绩同时展示。

合同要求最终独立复测时，实际完成后才宣布严格验收通过。主测与独立结果不一致，保留双方并诊断；不以主测通过覆盖可信回归，不只重跑负面项直到变好。采用例外不替代必要独立复测，也不把幅度稳定性超限改记为严格通过。
